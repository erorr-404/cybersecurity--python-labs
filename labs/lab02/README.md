# Лабораторна робота №2: Розробка консольних утиліт для задач кібербезпеки

**Варіант 3:** Валідатор та аналізатор конфігурацій правил фаєрвола.
## Опис проєкту

Проєкт складається з двох основних частин:

1. **Завдання 1 (`task1.py`):** Об'єктно-орієнтована модель користувачів, адміністраторів, безпечних сесій та системи аудиту (з використанням хешування PBKDF2-HMAC-SHA256 для захисту паролів).

2. **Завдання 2 (`task2.py`):** Консольна утиліта (CLI) для перевірки, валідації та аналізу цілісності правил мережевого екрана (фаєрвола).
## Установлення залежностей

Перед початком роботи переконайтеся, що ви активували віртуальне середовище, створене в попередній лабораторній роботі. З кореня репозиторію виконайте команду для встановлення всіх необхідних пакетів (зокрема `ruff` та `rich`):

```bash
pip install -r requirements.txt
```
## Вхідні дані та структура файлів

Утиліта приймає на вхід файл формату JSON, що містить масив об'єктів із конфігураціями правил фаєрвола (ID, Source, Destination, Port, Action).

Після розпакування архіву lab2_data.zip, тестові дані для 3-го варіанта повинні бути розміщені у відповідному каталозі data/data_v03/.
#### Структура файлів:
```
labs/lab02/
├── data/
│ └── data_v03/
│ └── firewall_rules.json
├── task1.py
├── task2.py
├── main.py
└── README.md
```
## Приклади запуску
### Завдання 1: Демонстрація ООП (команда demo)
Для запуску сценарію, який демонструє успішний/невдалий вхід, валідацію пошти, роботу прав адміністратора, таймаути сесій та систему AuditLog, виконайте:

```bash
python -m labs.lab02.main demo
```
### Завдання 2: Аналізатор правил фаєрвола
Для запуску CLI-утиліти аналізу фаєрвола використовуйте модуль task2 (із зазначенням фактичних шляхів до файлів):
```bash
python -m labs.lab02.task2 \
--rules-file labs/lab02/data/data_v03/firewall_rules.json \
--output labs/lab02/data/data_v03/fw_audit_report.json \
--check-conflicts \
--log-level DEBUG
```
## Опис параметрів CLI

Утиліта підтримує такі аргументи командного рядка:
- `--rules-file `(обов'язковий): Шлях до вхідного JSON-файлу з правилами фаєрвола.
- `--output` (обов'язковий): Шлях до файлу, у який буде збережено очищений список валідних правил (без конфліктів та дублікатів).
- `--check-conflicts` (необов'язковий, прапорець): Якщо вказано, вмикає перевірку на суперечливі правила (наприклад, коли одне правило дозволяє трафік для конкретних IP/портів, а інше аналогічне — блокує).
- `--log-level `(необов'язковий): Рівень деталізації консольного логування подій. Допустимі значення: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. За замовчуванням — `INFO`.
## Поведінка при помилках
Утиліта стійка до помилок та обробляє винятки на кількох рівнях:
- **Файл не знайдено:** Якщо вказано неправильний шлях до `--rules-file`, програма згенерує критичну помилку в логері та завершить роботу.
- **Зламаний JSON:** При спробі зчитати пошкоджений файл буде перехоплено `json.JSONDecodeError`, утиліта виведе повідомлення `ParsingError` із деталями синтаксичної помилки та зупинить роботу (код завершення `1`).
- **Помилки валідації записів:** Якщо окреме правило у JSON-файлі містить недійсну IP-адресу (наприклад, `999.10.1.1`), неправильну маску підмережі, невідому дію (не ALLOW, DENY чи BLOCK) або пропущене ключове поле — **програма не зупиняється**. Таке правило пропускається при побудові базового списку, записується у `InvalidRecord`, а після завершення парсингу логер видає попередження (`WARNING`) і виводить детальну таблицю з ID правила та причиною відхилення.
